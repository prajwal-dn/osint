Data Provenance & Transparency

Every component of this simulation is grounded in real, publicly available reference data or clearly labelled synthetic generation — not guesswork. This page explains exactly what powered each part of the tool and why it's defensible as a benchmark demo. Live querying of identifiable individuals is out of scope: it requires case-authorised production access under India's Digital Personal Data Protection Act §17(1)(c). That boundary is intentional.

📚 FEBRL / Record Linkage Toolkit
Real · Peer Reviewed

Ground-truth duplicate labels used to train & validate the XGBoost entity-resolution model. Reported F1 / precision / recall are defensible benchmark numbers, not eyeballed on self-generated data. Dataset from Christen (2008) — openly redistributable for research.

📮 India Post PIN Directory
Real · Public (data.gov.in)

PIN → city / district / state mapping. A real public aggregate reference used to place synthetic personas in structurally valid Indian locations. No personal data is derived from this source.

⚖️ NCRB Crime Taxonomy + eCourts CNR
Real · Public Format / Stats

NCRB published crime-category distribution drives realistic case-type mixes. eCourts' 16-char CNR format makes mock case IDs structurally correct — no real case records are queried or stored.

🧬 Synthetic Persona Layer
Synthetic · No Real People

Faker(en_IN) name pools + real reference data = 250 personas with schema-accurate social handles, Indian phone formats (E.164), and mock breach records. Adapters mirror live Sherlock / eCourts / VirusTotal API shapes.

🧠 XGBoost Entity-Resolution — 8 Input Features
Trained on FEBRL4 · F1 ≥ 0.97
given_name_sim
Jaro-Winkler
First name similarity — handles typos, transliteration variants (e.g. "Priya" vs "Priyaa")
surname_sim
Jaro-Winkler
Last name similarity — catches common suffix drops and regional spelling differences
street_sim
Jaro-Winkler
Street number string match — weak signal alone, strong signal in combination
suburb_sim
Jaro-Winkler
Area / locality name similarity — useful for detecting relocated vs. duplicate records
state_sim
Jaro-Winkler
State name match — low-entropy but stabilises borderline confidence scores
dob_exact
Exact match
Date of birth — highest-weight feature; shared DOB strongly predicts true duplication
postcode_exact
Exact match
6-digit PIN code — discriminates across large persona pools effectively
id_sim
Jaro-Winkler
Social / UID field similarity — catches transposed digits in government IDs
